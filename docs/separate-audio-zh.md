# cg.6：动画与配音分成两个文件

`<video src="movies/…">` 自带音轨的行为没有改变。cg.6 另行修复了独立 `<audio>` 节点：有些脚本用无声影片播画面，用另一个 Ogg/M4A 文件播配音。cg.5 的 DOM 音频节点即使返回 `play()` 成功也不会解码声音，不能产生自然的音频 `ended`。新版本捕获并使用 nx.js 原生 `Audio`（FFmpeg 解码和 Web Audio 输出），为 `document.createElement('audio')`、`new Audio(src)` 和 `Audio` 的 `<source>` 子节点提供相同的本地媒体行为；没有给无声影片自动“编造配音”。游戏仍负责选择音轨，以及何时一起开始。

## 上机试两段

从 hbmenu 的**应用模式**启动 `BurialNX 0.1.6-cg.6`，不要用包着旧代码的独立 forwarder。添加 `BurialNX-Sidecar-CG/www` 并选独立测试存档位置。样例不使用商业素材，不写剧情存档，不会自动开始。

以舒适音量按 A。两段各约 4 秒，各有四次白闪和四个提示音；对闪光敏感者可以跳过。视频文件**没有音频轨道**。左声道提示音为 440 Hz，右声道为 880 Hz，均来自单独的 Ogg。第一段通过 DOM `.src` 播放配音，第二段使用 `new Audio()` + `<source>`（先缺失候选、再正确文件）。两段之后应显示 `DONE 2/2`，按 A 可以重播。若只有运动图案和白闪却没有声音，或者片尾卡住，应记为没有通过。

## 边界

- 只读本地游戏/模组资源或本进程已有的 Blob，不开放网络访问。独立声音用原生 `Audio` 缓冲解码；普通本地路径的压缩输入限 64 MiB，较长音轨仍需足够解码内存。自带声音的普通 SD 视频仍可走原来的流式路径。
- 同一元素重复 `play()` 不重启。支持候选音轨回退、早于解码完成的 `play()`、暂停/继续、静音、音量、正数播放速率和循环。替换片源、关闭菜单/游戏时旧回调不会给新片源误报就绪或片尾。
- 设备体验仍以原场景为准。桌面运行发布包 JS 并测量混音总线，不等于已经在实体 Switch 和实际扬声器/HDMI 上运行。
