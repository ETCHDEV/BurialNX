# cg.5：CG 的声音和画面不在同一时刻结束

cg.4 有一类会卡住剧情的片源：视频 4 秒、配音 1 秒，音频样本耗尽后播放器时钟会反复回到 1 秒附近。因此最后的画面没有被呈现，也没有自然 `ended`。强制跳过视频只会掩盖问题。

cg.5 将**实际输出时钟**与**真实输入 PCM 的消费计数**分开。没有音频样本的时候，正在运行的音频设备仍然经过了时间，视频必须继续；反过来，音频长于图片轨时，最后一个有效画面必须保持到声音也播完。音频按解码后的呈现时间排队，保留延迟起音、循环里的间隔与 Opus 的 pre-skip 语义。不会修改用户的影音文件，不通过超时假装播放成功。该修复同时保留 cg.4 的“先接好音频节点再解码”。

## 两段即可在 Switch 上观察

1. 用应用模式从 hbmenu 打开 cg.5，选择 `Add Game → BurialNX-Tail-CG/www`（旧的独立 forwarder 可能仍内嵌旧 NRO）。测试目录不需要购买游戏，也不读写商业游戏的进度。选择独立测试存档位置即可。
2. 读完提示，以舒适音量按 A。**第一段**：4 秒画面，声音只有约 1 秒；声音停后图案继续动，约 3.5 秒处变为绿色，最后回到中间剧情画面。
3. **第二段**：运动画面约 1 秒，较早变为绿色并保持；还能听到声音，要到约第 4 秒才回到最后的剧情画面。看到 `DONE 2/2`。按 A 可以重播。

以上标准不是“等了 4 秒”或“回调发生了”：影片中的绿色末帧、两段声音各自的实际长度，以及回到剧情后的画面都必须对上。测试信号为可分辨的左右声道，不是对每台主机/电视的物理输出延迟做校准。普通全屏与 Pixi 小窗自检继续保留。

## 对照与复核

- 基线与修复版都使用相同的两段编码文件和同一份 MIT 发布的 RPG Maker MV `Graphics.js` / `Game_Interpreter.js` / `ResourceHandler.js`，没有改写引擎的 261（播放影片）、等待逻辑或 355（下一条剧情脚本）。
- `tests/movie-tail-probe.cc` 读取实际呈现的 BGRA 像素与设备大小的 1024 帧双声道 PCM；`tests/check-tail-matrix.py` 检查短音轨、短画面、延迟起音、无音轨、暂停、定位及循环。`tests/packed-movie/unequal-tracks.mjs` 从 SD ZIP 读应用和测试场景；`inspect-tail-recording.py` 只读最终带声录屏，独立检测绿色末帧、剧情底色、左右声道和声音长度，不读取播放器日志。
- 编译原生部分须依次应用 `nxjs-video-audio-preroll.patch` 和 `nxjs-video-track-timeline.patch`；见 `runtime/README.md` 和 `runtime/manifest.json`。
- 上述自动结果为桌面运行包内脚本、匹配的同源原生媒体核心的结果；NRO 本身已交叉编译为 Switch ARM64。**未代替实体 Switch 实测，不保证任意商业插件、编码或高码率影片。**
