# 动态 CG：可选真机自检包

这是给 **BurialNX 0.1.6-cg.6** 用的独立测试目录。它不替换 NRO，不收集麦克风、录音、截图、设备编号或账号，不联网。对商业游戏只需测试你已合法持有的本地片段，**不用上传素材**。

## 运行

1. 已安装 cg.6 的话，只需把自检 ZIP 里的 `BurialNX-CG-device-check/` 复制到 SD 卡根目录；不需要覆盖 `/switch` 或原游戏。没装 cg.6 的话先装普通版，从 hbmenu 的**应用模式**启动主程序，不要用内嵌旧代码的快捷启动器。
2. `Add Game` 选择 `BurialNX-CG-device-check/www`。建议为这个自检目录选独立的 SD 存档位置，不导入已有存档。测试不会改游戏进度；启动器自身仍会像平常一样记录游戏库。
3. 用方向键选择，按 A 查看提示，再按 A 才开始。第一项连续检查两种格式，中间需要确认；每段 4 秒，约每秒一次白闪和短音，共 4 次。**对闪光敏感请跳过自带样片**。建议音量适中，测试时不要开暂停菜单或让主机休眠；长按 X 可停止当前片段。
4. 要测原先黑屏的那段，请在电脑上**复制，不要移动原件，也不用转码**：MP4 副本命名为 `www/movies/my-cutscene-mp4.mp4`，选 `My own MP4`；WebM 副本命名为 `www/movies/my-cutscene-webm.webm`，选 `My own WebM`。请保留正确的扩展名。单独测试片源不会顺带验证原游戏插件、加密资源加载或具体剧情逻辑。
5. 每段片尾会依次出现两块校验色；测试器从最终显示画布读回两种颜色才算成功返回。随后逐项回答：**画面动了吗？听到声音了吗？音画对得上吗？** `A = 是`，`B = 否`，`Y = 没检查 / 不确定`。最后单独询问是不是实体 Switch。程序不会替你填“是”。
6. 汇总页可按 B 不保存；只有按 A 才会把这份自检报告写到 **`sdmc:/switch/burialnx/CG-CHECK/result-*.json`**。屏幕会显示文件名。每次保存新文件，不主动覆盖已有报告。你可以把 JSON 发回分析；不需要游戏文件、存档或任何密钥。

## 如何判断

- `OBSERVED_PASS_FOR_TESTED_CLIPS`：从当前 NRO 读到 cg.6、cg.5、cg.4、cg.3 或 cg.2 版本（此工具对两者检测全屏 CG；并非 Pixi 纹理验收），自动画面、时间推进、片尾恢复检查都满足；操作者也在每个片段确认看到运动、听到声音、音画匹配，并确认在实体 Switch 上运行。结论**只对本次所测片段、主机与输出方式有效**。
- `PROBLEM_OBSERVED`：真机运行时检测到片源/解码/超时问题，或操作者至少有一项回答了“否”。请看对应片段的 `problem`、`assessment` 和 `operator`。如果片源本来就无声，这一项不能验证有声播放。
- `INCONCLUSIVE`：还不能判断，比如不知道声音是否对齐、屏幕读回不可用、无法读取当前 NRO 版本、采样点没有运动等。自定义片段可能本来就有长黑场、静帧或可变时长，这不应自动解释为解码器损坏。
- `NO_PHYSICAL_CONFIRMATION`：操作者没有确认使用实体 Switch。桌面/模拟测试即使通过画面检查，也不记作真机通过。

参考样片另需至少实际呈现 86 帧、呈现帧占解码总帧的至少 90%，且实测时钟接近片尾才通过；这是这两个样片的验收条件，不是所有影片“零丢帧”的保证。可视采样有开销，自检不是性能基准。

报告中的 `media` 是解码尺寸、播放时间、呈现与丢帧计数；`screen` 是对**最终屏幕画布**降采样得出的运动及白闪次数，不保留像素；`returnMarkers` 是按顺序观测到的两块片尾校验色。`operator` 才是听感及感知同步的来源；程序**不能隔空听见扬声器，也不测 HDMI 的物理延迟**。个人片段只记录固定测试代号。读到的 NRO 显示版本本身不是硬件身份证明。

如果自检包里的自定义片段流畅、同一片段回到游戏里却黑屏，最有用的信息是：**游戏版本、触发场景、是否启用模组，及声音/动作/片尾哪一项不对**。这时应排查游戏侧的播放调用，而不是重新编码整个游戏。
